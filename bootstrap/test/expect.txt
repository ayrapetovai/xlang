# Expected behaviour for cases/*.x, checked by check.sh.
#
#   === <name> rc=<expected exit status>
#   --- out
#   <exact expected stdout, omitted if empty>
#   --- err
#   <exact expected stderr, omitted if empty>
#
# The case name is cases/<name>.x.
#
# rc 0 = parsed, 4 = rejected. Nothing else is accepted: check.sh flags any
# other status, including a crash (>= 128).
#
# --- out is the AST dump, pinned in full. "stmt" appears once per statement,
# so the shape of the dump *is* the expected parse tree; a change to the
# grammar or the printer shows up here as a readable diff rather than a
# changed hash.
#
# --- err is the diagnostic, pinned in full. Diagnostics go to stderr, so a
# regression that moves them to stdout, or drops them, is caught as a channel
# change and not just a text change.
#
# A case may declare extra assertion blocks after its dump:
#
#   === <name> run rc=<status>    what --run prints (the run layer)
#   === <name> chk rc=<status>    what --chk reports (the check layer)
#
# Both have the same --- out / --- err shape, and a chk block may use
# rc 1 = rejected by the checker. A chk block is how a program the parser
# accepts but the checker rejects is recorded; a case without one must pass
# --chk silently.
#
# Everything is compared byte for byte. When a case's expectation changes it
# must be edited by hand -- that edit is the review.
