Your are free to choose, any combination of T, &T, *T (or with const), or &value, *value (or with const) too express the exact rules:

- The `defer` operator fires at the end of the lifetime where it was defined.
- Memory deallocation must be implicit.
- Destruction (by `dispose` if defined) must be explicit, otherwise compilation error.
- The `dispose` function always have memory deallocation machinery for the passed parameter at the end of it's lifetime.
- The `dispose` function can take more then one argument, but the first one, must be taken by ownership transferring.
- If value is owned it must be passed to the other owner or be destroyed at the end of lifetime, or moved-out (returned).
- When ownership is passed there is no need to copy value, it may be passed by reference (or by value if it is an integral type like int, bool etc.).
- Memory deallocation machinery generated by compiler in `dispose` function (if defined) at the end of the body.
- If `dispose` function is defined without move semantics it is a compile-time error, `dispose` must take ownership.
- When the ownership of the value if passed to a block of code, `spawn`ed function of function, then this value no longer can be used in code after the point of ownership transmission.
- If caller owns value it can transfer the value without transferring the ownership by providing a view of the value. 
- If function does not own value it may not destroy it, calling `dispose` on non-owned value is a compilation error.
- No partial consuming, if the struct's field is consumed then the whole struct treated as consumed. To consume - to take ownership, and not to give it back.
- Mutable view - is to pass variable by reference with availability for callee to mutate the value, mutable view can be passed only to the functions with lifetime, that is surround by lifetime of the owner of the value.
- If function call other function, it can pass mutable view, if function spawns a coroutine (different lifetime), then it is a compile error to pass mutable view, only transferring ownership allowed, the exception is intrinsics: mutex, atomic and channel. Because the they are handled by reference counting pointer, the deallocation machinery for them must be embedded at the end of the lifetime the appeared in.
- if function returns value with ownership transferring it cannot be assign to non-owning variable, it is a compile error.
